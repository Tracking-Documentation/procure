# ระบบจองวันลงนามสัญญาออนไลน์ (Google Apps Script)

บริษัทสแกน QR Code ในหนังสือเรียกลงนามสัญญา → เลือกวัน/เวลา (09.00–15.30 น. ช่วงละ 30 นาที, 1 ช่วงเวลา = 1 โครงการ) → กรอกผู้ติดต่อ → ระบุผู้ลงนาม (กรณีไม่มอบอำนาจต้องกรอกชื่อ นามสกุล ตำแหน่ง) → แนบเอกสาร → ได้เลขที่สัญญาเบื้องต้นทันที

- ข้อมูลเก็บใน Google Sheet (ชีต `projects`, `bookings`, `settings`) ไฟล์แนบเก็บใน Google Drive โฟลเดอร์ `เอกสารจองลงนามสัญญา`
- จองได้เฉพาะวันทำการภายในกำหนด (นับจากวันที่บริษัทได้รับหนังสือ) และหลังพ้นระยะอุทธรณ์ ช่วงวันส่งมาจากแอป
- เลขที่สัญญาเรียงตามวันและเวลาที่นัด แยกตามปีงบประมาณ (เริ่ม 1 ต.ค.) เลขที่เจ้าหน้าที่ยืนยันแล้วจะไม่เปลี่ยน
- รูปแบบเลขกำหนดในแอป หน้าตั้งค่า เช่น `{n}/{yyyy}` (`{nnn}` = เติมศูนย์ 3 หลัก)

## ติดตั้ง
1. สร้าง Google Sheet ใหม่ → ส่วนขยาย › Apps Script
2. วางโค้ด `Code.gs` · เพิ่มไฟล์ HTML ชื่อ `Booking` แล้ววางโค้ด `Booking.html`
   - QR จองวันลงนามสัญญาเปิดหน้า `book.html` บนเว็บเดียวกับระบบ (สร้างจาก `Booking.html` ด้วย `python3 .mkbook.py`) แล้วเรียก Apps Script เบื้องหลัง จึงไม่ติดปัญหาล็อกอิน Google หลายบัญชี (`/u/1/`) · ลิงก์ QR เดิม (script.google.com) ยังใช้ได้
3. แก้ `ADMIN_KEY` ใน Code.gs เป็นรหัสลับยาวอย่างน้อย 16 ตัว (ผสมตัวอักษรและตัวเลข) → บันทึก · **ห้ามนำไฟล์ที่ใส่รหัสจริงขึ้น GitHub**
4. เลือกฟังก์ชัน `setup` → Run → อนุญาตสิทธิ์
5. Deploy › New deployment › Web app · Execute as **Me** · Who has access **Anyone** → คัดลอก URL `/exec`
6. ในแอป หน้าตั้งค่า › “QR จองวันลงนามสัญญาอัจฉริยะ” ใส่ URL และรหัส → ทดสอบการเชื่อมต่อ → ส่งรูปแบบเลขที่สัญญา
7. แก้โค้ดภายหลัง: Deploy › Manage deployments › Edit › Version: New version (URL เดิม)

## บัญชีผู้ใช้และข้อมูลกลาง (เพิ่มใน v45)
Web app ตัวเดียวกันนี้เป็นเซิร์ฟเวอร์เข้าสู่ระบบและเก็บข้อมูลโครงการที่ทุกเครื่องใช้ร่วมกัน
- ชีต `users` เก็บบัญชี (รหัสผ่านเป็นแฮช อ่านย้อนกลับไม่ได้) · ชีต `store` เก็บข้อมูลโครงการและค่าตั้งค่าที่ใช้ร่วมกัน
- สิทธิ์: ผู้ดูแลระบบ (จัดการผู้ใช้) · แก้ไขได้ · ดูได้อย่างเดียว · เข้าสู่ระบบครั้งหนึ่งอยู่ได้ 7 วัน · กรอกรหัสผิด 5 ครั้งล็อก 10 นาที
- ตั้งรหัสใหม่ เปลี่ยนรหัส หรือปิดบัญชี → เครื่องที่เข้าอยู่ถูกออกจากระบบทันทีที่ซิงก์ครั้งถัดไป
- เปิดใช้: อัปเดต Code.gs → Run `setup` → Deploy › Manage deployments › Edit › Version: New version → ในแอป หน้าตั้งค่า › “บัญชีผู้ใช้และข้อมูลกลาง” สร้างบัญชีผู้ดูแล (ใช้ ADMIN_KEY ครั้งแรกครั้งเดียว)
- ผู้ใช้อื่น: ผู้ดูแลกด “คัดลอกลิงก์ติดตั้งให้ผู้ใช้” แล้วส่งให้ เปิดลิงก์ → เข้าสู่ระบบ → ติดตั้งแอป
- ห้ามแชร์ Google Sheet นี้ให้คนที่ไม่ใช่ผู้ดูแล เพราะข้อมูลทุกโครงการอยู่ในนั้น

## ซิงก์จากชีตระบบติดตามเดิม (เพิ่มใน v77)
- แอปดึงข้อมูลจากชีต “สถานะโครงการจัดซื้อจัดจ้างรวม งบประมาณปี ...” (`LEGACY_SHEET_ID` ใน Code.gs) ทุก 5 นาที หรือกดปุ่ม “ซิงก์จากชีตเดิมตอนนี้” ในหน้าตั้งค่า
- ซิงก์: โครงการ (ชื่อ ID เลข e-GP กม. วงเงิน วันที่ต่าง ๆ) คณะกรรมการ TOR/ราคากลาง/พิจารณาผล คณะกรรมการตรวจรับและผู้ควบคุมงาน (ป/ก/ค/ผช) ทำเนียบรายชื่อกรรมการ
- ค่าที่เปลี่ยนในชีตจะทับค่าในแอป · ค่าที่ชีตไม่ได้เปลี่ยนจะไม่ไปทับสิ่งที่แก้ในแอป · โครงการใหม่ในชีตเพิ่มเข้าแอปให้เอง
- บัญชี Google ที่ Deploy เว็บแอปต้องเปิดชีตนั้นได้ (ถ้าเป็นคนละบัญชีกับเจ้าของชีต ให้แชร์ชีตให้บัญชีนั้น)

## ความปลอดภัยและข้อมูลส่วนบุคคล (เพิ่มใน v151)
- รหัสเจ้าหน้าที่ (`ADMIN_KEY`) กรอกผิดเกิน 10 ครั้ง ล็อก 15 นาที · รหัสสั้นกว่า 16 ตัวหรือยังไม่เปลี่ยน ระบบปิดการใช้รหัสนี้ (ใช้บัญชีผู้ใช้แทน)
- แอปส่งรหัสและโทเค็นด้วย POST ไม่ใส่ในลิงก์
- หน้าจองแสดงประกาศการคุ้มครองข้อมูลส่วนบุคคล และให้บริษัททำเครื่องหมายรับทราบก่อนจอง
- ลบไฟล์ที่บริษัทแนบอัตโนมัติ: ตั้ง `FILE_RETAIN_DAYS` ตามที่หน่วยงานเห็นชอบ (เช่น 365) แล้ว Run `setupPurgeTrigger` ครั้งเดียว
- ตรวจการแชร์: Google Sheet ของระบบ ชีตระบบติดตามเดิม และโฟลเดอร์ Drive ต้องตั้งเป็น “จำกัด” ไม่ใช่ “ทุกคนที่มีลิงก์”
